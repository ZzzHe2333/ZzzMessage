# ZzzMessage 群聊、Telegram 风格 UI、表情及附件使用指南

## 已提交的功能

1. 群聊：创建后前端立即进入新群、刷新服务器最新房间。WebSocket 无法通过内网穿透时，GET /api/messages/pending 也会返回当前账号的 rooms，用于每次轮询修正群列表。创建群本身不发送系统消息，但群内后续文字和附件会进入按成员隔离的持久队列和通知。
2. Web/iPhone PWA：Telegram 风格三栏（会话/聊天/资料），左侧搜索、汉堡菜单，顶部显示会话对象/群名及人数；浏览器页签 title 随会话变化，移动端采用会话列表和聊天切换。
3. 表情：支持输入框旁的 Emoji 选择器，选择后插入 Unicode 文本。服务端不需要特殊转码。
4. 文件：单次上传最大 10 MiB，服务器保存在 DATA_DIR/uploads/<随机ID>.blob，附件元数据及对应消息保存在 state.json。消息进入与文字相同的离线待投递队列，网页通过认证 GET /api/files/{id} 下载。图片等文件也通过附件下载，不自动在网页执行 HTML/JS 内容。

## 客户端使用

- Web/iPhone PWA 登录后，左侧列表进入某个会话。菜单中新建群聊，选择成员并创建；无需等待对方在线。
- 点击聊天输入框左侧笑脸打开 Emoji；点击回形针选择文件，上传后自动发送到当前群/私聊。点击文件消息下载。
- 点击聊天顶部的头像与会话名称打开右侧资料抽屉，支持查看群成员及本机已同步的附件列表。
- 通知仍由 VAPID 和 Web Push 提供。Edge 订阅必须能被后端接收；首次使用或变更密钥后可从设置中重置旧订阅。

## API 和安全

| API | 要求 | 功能 |
|---|---|---|
| POST /api/files/upload | Bearer 用户登录令牌、multipart(roomId,file) | 先存储文件再创建持久化文件消息；限制每个文件 10 MiB |
| GET /api/files/{id} | Bearer 用户登录令牌 | 仅会话成员可下载；服务器返回 Content-Disposition: attachment |
| GET /api/messages/pending | Bearer 用户登录令牌 | 现包含 messages 和 rooms 两个字段，兼容旧客户端 |

错误处理：无权上传返回403，下载无权文件返回404（不暴露文件是否存在），过大返回413；只允许已注册登录用户操作，不因知道文件 ID 就开放下载。每个文件随机ID，原始文件名只记录为显示字段，不参与磁盘路径。

注意：附件存储仅有限制大小和数量（2000 个），没有清理/完整审计功能。服务器会持有完整附件，不是端到端加密。请保护 DATA_DIR/uploads 与 state.json，并通过 HTTPS/可信反向代理提供服务。已有的 14 天/500 条待投递限制针对消息正文，不会自动删除附件二进制。

## 验证清单

Windows Edge → 允许通知 → 点击测试通知；Android Chrome → HTTPS → 订阅推送；iPhone 桌面 PWA → 通知/群聊/附件。创建一个两人群、离线登录另一个账号，确认群名和消息出现；尝试通过第三个不在群里的账号访问附件下载，预期404。

本指南对应 GitHub main 开发源码。自动化 Go/Web 构建通过不等于已在 Windows/Android/iPhone 真机上完成全面端到端验证；发布之前请备份用户数据。
